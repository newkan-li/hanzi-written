# 1. 项目概述

**墨学** 是一个面向硬笔书法与汉字书写练习的开源微信小程序，核心功能围绕「看笔顺、跟着写、做测验」展开，帮助用户掌握汉字的正确书写顺序与结构。

主要功能：

1. **笔顺动画演示**：逐笔播放汉字的正确书写顺序。
2. **描红跟写**：显示字的外框与提示，用户用手指跟着描红。
3. **笔顺测验**：隐藏提示，用户凭记忆书写并即时判定。
4. **多格子样式**：田字格 / 米字格 / 回宫格 / 横线格 / 无格，可切换并记忆。
5. **汉字详情**：拼音、部首、笔画数、结构、组词、释义（本地小字典）。
6. **每日打卡**：连续打卡天数、最近 7 天、累计天数。
7. **字帖生成与导出**：按来源（当前字表 / 收藏 / 模板 / 自选）生成字帖，导出保存或分享。
8. **字帖模板**：静夜思、春晓、咏柳、百家姓、弟子规、成语等。
9. **成语练字**：常用四字成语（拼音 + 释义），按字练习。
10. **生字本**：描红 / 测验中写错的字自动收录，便于重点复习。
11. **自由书写画板**：手指书写，支持范字临摹、田字格、撤销、颜色/粗细、保存图片。
12. **练习轨迹**：把书写作品加入轨迹记录，可预览 / 删除 / 清空。
13. **分享海报**：生成练习成果海报并保存 / 分享。
14. **朗读发音**：调用 TTS 音源朗读当前汉字。
15. **练习记录与收藏**：本地记录练习过的字、次数与收藏，零后端成本。
16. **教材同步字库**：部编版（统编版）1–6 年级识字表/写字表，按「册 → 单元 → 课」浏览、练本课、生成本课字帖。
17. **教材听写**：按课 / 单元 / 册听写测试（看拼音选字、TTS 朗读、计分，错字进入生字本）。
18. **课本古诗**：部编版课文古诗 113 首（按册浏览、看原文、练整首、生成字帖）。
19. **首页教材联动**：今日一课（395 课轮换）、今日一诗、年级入口、最近练习。
20. **单元/册测试卷**：看拼音选字 + 看字选拼音混合出题，计分与错题回顾，错题自动进生字本。

设计目标是：**以尽可能低的成本（开发成本、运维成本、合规成本）交付一个可用的练字小程序**。

# 2. 技术选型

## 2.1 选型结论

| 维度 | 方案 | 说明 |
| --- | --- | --- |
| 宿主平台 | 微信原生小程序 | 只做微信端，包体/性能最优，无需跨端框架 |
| 笔顺内核 | `hanzi-writer` + 小程序封装（**内置 vendored**） | 放在 `vendor/hanzi-writer/`，提供动画、描红、测验全套能力，免构建 |
| 笔画数据 | `hanzi-writer-data`（jsDelivr CDN） | 按需加载 + 本地缓存，避免撑大包体 |
| 数据存储 | 本地 Storage | 免后端、免服务器、免备案 |
| 构建 | 无（源码内置，克隆即用） | 不依赖 npm 与「构建 npm」 |

## 2.2 为何不用 uni-app / Vue

- 本项目**只发微信一个小程序**，uni-app 的跨端优势用不上，反而多一层构建与适配成本。
- 若未来确定要跨端（App / H5 / 多小程序），再迁移到 uni-app + `lime-hanzi-writer` 更划算。
- 从**费用角度**，原生与 uni-app 都不产生授权费；差异只在于跨端时节省的人力，而非运行成本。

## 2.3 成本相关结论

技术栈本身**不产生费用**，真正的成本点在：

1. **类目资质**：书法/汉字教学若归入「教育」类目，可能需要办学许可等资质。本项目按「**工具类目**」定位（笔顺查询、练字工具），规避资质门槛。
2. **后端**：本项目零后端，成本为 0。
3. **变现**：流量主需累计 UV 1000+（免费开通）；付费课程/会员需企业认证（300 元/年）与微信支付商户号（费率约 0.6%）。
4. **小程序认证**：个人主体可免费注册；企业/组织认证 300 元/年。

## 6.2 utils/charData.js —— 字库加载核心

提供唯一的对外方法 `loadCharData(char): Promise<Object>`。

**四级加载策略（按优先级）：**

| 层级 | 说明 | 是否计入包体 |
| --- | --- | --- |
| 内存缓存 `memoryCache` | 同一次运行内避免重复读取/解析 | 否 |
| 内置字库 `data/embedded.js` | 手动预置的离线数据 | 是（慎用） |
| 本地文件缓存 | `wx.env.USER_DATA_PATH/char-data/<字>.json` | 否 |
| CDN 下载 | `config.charDataCDN/<字>.json` | 否 |

关键实现要点：

1. 使用 `wx.getFileSystemManager()` 读/写缓存文件。
2. 目录不存在时用 `mkdirSync(dir, true)` 递归创建。
3. CDN 请求使用 `wx.request`，HTTP 200 且返回体非空才视为成功。
4. 下载成功后异步写盘，不阻塞返回。
5. JSON 解析失败时按缓存未命中处理，回退到 CDN。

```js
async function loadCharData(char) {
  if (memoryCache[char]) return memoryCache[char]
  const embedded = require('../data/embedded')
  if (embedded && embedded[char]) { ... }
  let data = await readLocal(char)
  if (!data) { data = await fetchRemote(char); writeLocal(char, data) }
  memoryCache[char] = data
  return data
}
```

**离线能力**：用户练习过的字会落盘缓存，二次访问无需网络。首次使用需要网络。

## 6.3 utils/storage.js —— 记录 / 收藏 / 偏好 / 打卡 / 生字本 / 轨迹

本地存储键：

| 键 | 结构 | 说明 |
| --- | --- | --- |
| `hw_favorites` | `string[]` | 收藏的汉字，后收藏的在前 |
| `hw_records` | `{ [char]: { count, lastTime } }` | 每字练习次数与最近时间 |
| `hw_prefs` | `{ [key]: value }` | 偏好（如 `gridStyle`） |
| `hw_checkins` | `{ [YYYY-MM-DD]: count }` | 每日打卡 |
| `hw_weak` | `{ [char]: { count, lastTime } }` | 生字本（错字） |
| `hw_trajectory` | `[{ id, char, time, path }]` | 练习轨迹（图片存用户目录） |

对外 API：

| 分类 | 方法 |
| --- | --- |
| 偏好 | `getPref(key, def)` / `setPref(key, value)` |
| 收藏 | `getFavorites` / `isFavorite` / `toggleFavorite` / `clearFavorites` |
| 记录 | `getRecord` / `addRecord` / `getRecords` / `clearRecords` |
| 打卡 | `checkin()` / `getCheckinStats()`（返回 `streak` / `totalDays` / `todayDone` / `recent[7]`） |
| 生字本 | `getWeak()` / `addWeak(char)` / `removeWeak(char)` / `clearWeak()` |
| 轨迹 | `getTrajectory()` / `addTrajectory({char,path})` / `removeTrajectory(id)` / `clearTrajectory()` |
| 汇总 | `getStats()`（`charCount` / `totalCount` / `favCount` / `weakCount` / `days` / `streak`） |

> `addTrajectory` 会把临时图片 `copyFile` 到 `wx.env.USER_DATA_PATH` 持久化，最多保留 100 张。

## 6.4 Hanzi Writer 集成

组件与内核已内置在 `vendor/hanzi-writer/`（`index.js` 为控制器，`hanzi-writer-view.*` 为画布组件，`hanzi-writer.js` 为内核），**无需 npm 构建**。

### 组件注册（pages/practice/practice.json）

```json
{
  "usingComponents": {
    "hanzi-writer-view": "/vendor/hanzi-writer/hanzi-writer-view"
  }
}
```

### 视图（wxml）

```xml
<hanzi-writer-view id="hz-writer" width="{{size}}" height="{{size}}" />
```

`width` / `height` 为必填，单位与画布一致（px）。本项目按 `windowWidth * 0.8` 计算。

### 控制器（js）

```js
const createHanziWriterContext = require('../../vendor/hanzi-writer/index')

this.writerCtx = createHanziWriterContext({
  id: 'hz-writer',
  character: char,
  page: this,
  // 注意：charDataLoader 采用回调式 (char, onLoad, onError)，
  // 且“不要”返回值——返回真值会被当作字库数据，导致画布空白。
  charDataLoader: (c, onLoad, onError) => {
    loadCharData(c).then(onLoad).catch(onError)
  },
  onLoadCharDataSuccess: () => { /* 数据就绪 */ },
  onLoadCharDataError: () => { /* 加载失败 */ }
})
```

### 微信兼容修补（重要）

内置的 `vendor/hanzi-writer/` 做了两处兼容处理，源码版不具备：

1. **Path2D**：新版基础库暴露全局 `Path2D`，但 `new Path2D(pathString)` 在小程序不可用，会使 `ctx.clip(空路径)` 裁掉整字（静默空白）。已强制走微信兼容分支（先 `stroke` 再 `clip`）。
2. **全局解析**：内核的 webpack 全局注入使用 `eval`/`Function`，小程序沙箱禁止；已替换为 `globalThis/window/self` 安全解析。

### 画布就绪竞态

组件内部异步获取画布上下文，而字库可能（从缓存）立即返回；练字页在把数据交给 Hanzi Writer 前会等待画布节点就绪（`waitForCanvas`），否则首帧会因 `ctx` 未就绪而抛错并中断动画。

### 三种模式

| 模式 | 调用 | 说明 |
| --- | --- | --- |
| 演示 | `animateCharacter()` | 逐笔播放动画 |
| 描红 | `quiz({ leniency: 1.4, showHintAfterMisses: 1, markStrokeCorrectAfterMisses: 2 })` | 容错高、提示早，适合跟写 |
| 测验 | `quiz({ leniency: 0.9, showHintAfterMisses: 3 })` | 容错低、提示晚，适合检验 |

其他用到的关键选项：

- `showOutline`：是否显示字的外框（描红提示）。
- `strokeColor` / `radicalColor` / `highlightColor` / `drawingColor`：配色。
- `drawingWidth`：书写判定线宽。
- `padding`：字在画布内的内边距。

切换模式前调用 `cancelQuiz()` 重置；动画由 `animateCharacter()` 内部接管，无需手动 `hideCharacter()`。

## 6.5 数据生成与来源

- **教材/古诗数据**：由 `tools/gen-data.mjs` 从开源数据集 `fsiceangel/zishi`（部编版小学语文生字表）生成 `data/textbook.js` / `data/textbookPinyin.js` / `data/poems.js`，仅含事实性字表/拼音/原文。
- **主题分类字表**：由 `tools/gen-themes.mjs` 把**课本汉字按主题归类**，生成 `data/themeChars.js`（入门基础 / 日常常用 / 自然万物 / 品德修养 / 古诗名句），字库分类即读取它；语义分类为启发式，可扩充 `SEEDS` 词表重跑。
- **笔画数据**：由 `tools/fetch-strokes.mjs` 批量下载，用于上传自有存储、摆脱 jsDelivr。
- **手工数据**：`data/idioms.js`（成语）、`data/charInfo.js`（字典）为手工整理，不在生成脚本内。
- 脚本用法见 `tools/README.md`；发布与数据源本地化见 `docs/上线指引.md`。

## 7.2 字库页 pages/library

- 顶部**按教材**：一~六年级 × 上/下 册，点册跳 `textbook?book=<id>`。
- 中部**按主题**：入门基础 / 日常常用 / 自然万物 / 品德修养 / 古诗名句，字表由课本汉字按主题归类生成（`data/themeChars.js`，见 6.5），点分类跳 `category?key=<key>`。

## 7.3 分类页 pages/category

- `onLoad(options)` 按 `key` 从 `data/commonChars.js` 取分类。
- 4 列网格展示汉字，点击把整个分类列表写入 `globalData.practiceList` 并进入练字页。
- 方格用 `padding-bottom` 百分比实现正方形（不依赖 `aspect-ratio`）。

## 7.4 练字页 pages/practice

- 生命周期：`onLoad` 读取列表/索引、记录一次练习、写入今日打卡、读取 `globalData.practiceNote`（如成语/课文提示条）；`onReady` 创建 writer；`onUnload` 释放音频。
- 交互：模式（演示/描红/测验）、多格子样式（田/米/回宫/横线/无）、上一个/下一个（循环）、再写一遍、收藏、朗读、书写、海报、字帖。
- `charDataLoader` 为回调式 `(char, onLoad, onError)` 且不返回值；加载前 `waitForCanvas()` 等待画布就绪。
- 汉字详情：`data/charInfo.js` 提供拼音/部首/结构/组词/释义；笔画数取自笔画数据 `strokes.length`；组词可点击练习。
- 测验 / 描红：`quiz({ onMistake, onComplete })` —— 写错的字进入**生字本**（`storage.addWeak`）。
- 朗读：`config.tts`（含 `enabled` 开关）拼接音源，`wx.createInnerAudioContext` 播放。

## 7.5 字帖生成页 pages/worksheet

- 来源：当前字表 / 我的收藏 / 字帖模板 / 自选汉字（`data/templates.js`）。
- 参数：格子样式、列数、行数。
- `<canvas type="2d">` 绘制：标题、日期、格子、范字（首行深色、其余浅色描红）。
- 导出：`wx.canvasToTempFilePath` → `wx.saveImageToPhotosAlbum` 保存 / `wx.showShareImageMenu` 分享。

## 7.6 海报页 pages/poster

- 绘制 App 名、田字格大字、拼音、打卡/练习统计；`canvas 2d` 生成图片并保存 / 分享。
- 大字与拼音来自 `globalData.posterChar` 与 `data/charInfo.js`。

## 7.7 我的页 pages/profile

- `onShow` 刷新统计、打卡、收藏、最近练习（最多 50 条）。
- 打卡卡片：连续天数、最近 7 天、累计天数。
- 入口：生成练习海报、收藏生成字帖、**生字本**、**练习轨迹**、**关于与隐私**。
- 清空收藏 / 记录（带确认弹窗）。

## 7.8 教材同步字库 pages/textbook

- **数据来源**：部编版（统编版）小学语文 1–6 年级 12 册，转换自开源数据集 `fsiceangel/zishi`（`volumes.json` / `meta.json` / `chars.json`）。
- **规模**：识字表 3000、写字表 2500，去重 2999 字；395 节课。
- **数据文件**（主包，约 99KB，生成；仅存字符/拼音与分组，不含笔画数据）：
  - `data/textbook.js`：册/单元/课 + 识字表/写字表/例词
  - `data/textbookPinyin.js`：2999 字拼音表
- **结构**：

  ```js
  {
    books: [
      { id:'1a', name:'一年级上册', short:'一上', grade:1, term:1,
        shiziCount:300, xieziCount:100,
        units: [ { title:'第一单元', theme:'识字', lessons:['1a-s1', ...] } ] }
    ],
    lessons: {
      '1a-s2': { title:'金木水火土', kind:'识字', shizi:[...], xiezi:[...], words:[...] }
    }
  }
  ```

- **放在主包的原因**：约 99KB，远低于主包 2MB 上限；且首页需要读取它渲染「今日一课」，而主包不能引用分包数据。因此不使用分包。
- **交互**：选册（支持 `?book=1a` 直达）→ 识字/写字切换 → 单元/课列表 → 课内字网格（点单字练字）、例词（点词练词）、练本课、本课字帖；每课/单元/册提供「听写」「测试」。

# 9. 包体与性能

## 9.1 微信包体限制

- 主包 ≤ 2MB
- 单个分包 ≤ 2MB
- 所有分包合计 ≤ 20MB

## 9.2 为什么不能全量内置字库

全量约 9000+ 字，总体积十几 MB 以上，会突破主包/分包限制，且首次下载体验差。

## 9.3 优化策略

1. **小字库内置 + 大库按需缓存**（本项目默认策略）。
2. **分包/独立分包**：字库按分类拆分，按需预下载（`wx.loadSubpackage`）。
3. **本地文件缓存**：练过的字离线可用。
4. **内存缓存**：避免重复解析。
5. 组件与内核已内置在源码 `vendor/`，不占 npm 构建环节。

## 9.4 当前主包体积构成（参考）

| 部分 | 约体积 |
| --- | --- |
| `vendor/hanzi-writer`（内核 + 组件） | 约 106KB |
| `data/textbook.js` | 约 69KB |
| `data/textbookPinyin.js` | 约 30KB |
| `data/poems.js` / `idioms.js` / `charInfo.js` / `commonChars.js` | 合计约 40KB |
| 页面与样式代码 | 约 100KB |

整体约 340KB，远低于主包 2MB 上限；笔画数据始终走远程 + 缓存，不打包。

# 13. 常见问题（FAQ）

**Q1：练字页提示「字库加载失败」？**
A：多为域名未配置。开发时勾选「不校验合法域名」，或把 `https://cdn.jsdelivr.net` 加入 request 合法域名。

**Q1.1：提示「NPM packages not found」？**
A：本项目组件已内置在 `vendor/`，**不需要也不应**执行「构建 npm」。该提示通常是因为点了「工具 → 构建 npm」或仓库残留了 `package.json` / `node_modules`。删除它们后直接「编译」即可（本项目已不含 `package.json`）。

**Q2：练字页画布空白 / 没有字？**
A：内置组件已修补两个已知坑：新版基础库的 `Path2D` 与画布就绪竞态。若自行替换为官方 `hanzi-writer-miniprogram` npm 包，需注意 `charDataLoader` 必须用回调式且不返回值，并等待画布就绪。

**Q3：包体超限？**
A：不要把全量字库放进主包。使用默认的按需加载 + 缓存策略，或改用分包。

**Q4：如何离线内置部分常用字？**
A：安装 `hanzi-writer-data` 后，在 `data/embedded.js` 中 `require('hanzi-writer-data/我')` 预置少量高频字，注意控制包体。

**Q5：如何替换数据源？**
A：推荐用 `node tools/fetch-strokes.mjs` 下载笔画数据上传到自有存储，再改 `utils/config.js` 的 `charDataCDN`；详见 `docs/上线指引.md`。

**Q6：Linux 上怎么安装微信开发者工具？**
A：官方仅支持 Windows/macOS。Linux 使用社区移植版 `msojocs/wechat-web-devtools-linux`，下载其 `.deb` 安装（`sudo dpkg -i ... && sudo apt-get -f install`），或用 AppImage（需先 `apt install libfuse2`）。详见 3.4 节。

**Q7：保存到相册 / 分享无反应？**
A：这两类 API 在开发者工具里受限，请用**真机**验证；首次保存需授予相册权限（已做引导到设置）。
